📚 How to Study This Code

This is a reference implementation. Study these specific patterns:

  • Chained Fetches: This app does TWO fetches in a row. First, it asks Nominatim for coordinates (lat/lon). Then, it asks Open-Meteo for the weather. See fetchWeather().
  • Two-Step Fetch: await fetch(url) gets the Response. await response.json() reads the body. Both need await.
  • No API Key: By using Open-Meteo, we remove the friction of signing up for keys, making it easier for beginners to get started.
  • Three States: The UI has exactly three states: loading, error, weather card. showState(id) hides all three then shows one.
  • Destructuring: const { temperature, windspeed } = data.current_weather; pulls specific values out of a deeply nested object.

✏️ Try These Experiments:

  1. Click “Load Demo Data” and notice no network request happens. Then search for a city and watch TWO requests appear in the Network tab.
  2. In fetchWeather(), comment out the second fetch. What does the app show?
  3. Try searching for a city that doesn't exist (e.g., "Qwertyuiopasdf"). How does the app handle it?
  4. Modify displayWeather to show the weathercode. Use the Open-Meteo documentation to map codes to icons.
