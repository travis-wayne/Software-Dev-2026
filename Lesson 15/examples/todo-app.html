    📚 How to Study This Code

    This is a reference implementation. Don't just read it — study these specific patterns:

    • One source of truth: The tasks array is the ONLY state. The DOM is always rebuilt from it — never updated directly.
    • The Core Loop: Every action calls save() then render(). Find these calls in addTask, toggleTask, and deleteTask.
    • Event Delegation: There is ONE click listener on #task-list — not one per task. This handles dynamically created elements. See line ~238.
    • XSS Safety: Task text is set with .textContent, never .innerHTML. Find this in the render() function.
    • localStorage: save() uses JSON.stringify. The initial load uses JSON.parse(...) || []. Find both.

    ✏️ Try These Experiments:

    1. Add a task, open DevTools → Application → Local Storage. Can you see the JSON string?
    2. In the console, type localStorage.clear() then refresh. What happens to the tasks?
    3. Change the id: Date.now() to id: Math.random(). Does everything still work?
    4. Remove the if (!text.trim()) return; guard from addTask. What happens when you press Enter with nothing typed?
