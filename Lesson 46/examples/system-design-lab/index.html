The RESHADED Framework

Master the 8-step process for acing any system design interview.

Step 1 of 8
R

Requirements Clarification (~2-5 min)

  • Functional vs Non-functional requirements.
  • Ask: scale, latency, availability, consistency needs.
  • Template questions list.
Pro Tip: Never start drawing before asking questions!
E

Estimation (Back-of-the-Envelope) (~5-10 min)

  • DAU, QPS, storage, bandwidth.
  • Show formula: QPS = DAU × actions_per_day ÷ 86,400
S

Storage Schema Design (~5 min)

  • SQL vs NoSQL choice.
  • Key entities, primary keys, indexes.
  • Show URL shortener schema snippet.
H

High-Level Architecture (~10 min)

  • ASCII block diagram of components.
  • Client → Load Balancer → App Servers → Cache → DB → CDN.
A

API Design (~5 min)

  • Core REST endpoints.
  • POST /shorten, GET /{slug}, DELETE /{slug}.
  • Request/response JSON examples.
D

Detailed Design (~15 min)

  • Deep-dive on the hardest component (ID generation algorithms, cache eviction policy, DB sharding strategy).
E

Evaluate Bottlenecks (~5 min)

  • Where does the system fail at 10x load?
  • Which component scales first?
  • Single points of failure.
D

Deep Dive (Interviewer-Chosen) (~10 min)

  • Interviewer picks one area to explore further.
  • e.g., "How would you handle 1 billion users?", "What happens when the cache server goes down?"
