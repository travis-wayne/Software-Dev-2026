Database Design & Relationships

Learn how to structure data across multiple tables so that information is stored once, referenced everywhere — eliminating bugs, saving storage, and making queries blazing fast.

The Three Relationship Types

1:1

One-to-One

Each row in Table A links to exactly one row in Table B, and vice versa.

-- The FK is also UNIQUE

user_profiles(user_id UNIQUE)

↳ 1 user → 1 profile

1:N

One-to-Many

One row in Table A can link to many rows in Table B, but each B row links back to only one A.

-- FK in the "many" side table

posts(user_id FK)

↳ 1 user → many posts

M:N

Many-to-Many

Many rows in Table A can link to many rows in Table B. Requires a junction table.

-- Junction table = bridge

post_tags(post_id, tag_id)

↳ post ↔ many tags, tag ↔ many posts

What is Normalization?

Normalization is the process of structuring a database to reduce redundancy and improve data integrity. Think of it as the "DRY principle" for databases.

❌ The Redundancy Problem — Before Normalization

order_id customer_name customer_email customer_city product
1001Alice Smithalice@email.comLagosLaptop
1002Alice Smithalice@email.comLagosKeyboard
1003Alice Smithalice@email.comLagosMouse

⚠️ Alice's info is stored 3 times. If she moves cities, you must update 3 rows (and risk inconsistency).

✅ After Normalization — Data Stored Once

customers table

idnameemailcity
1Alice Smithalice@email.comLagos

orders table

idcustomer_idproduct
10011Laptop
10021Keyboard
10031Mouse

✅ Alice's city is stored once. Update 1 row → all 3 orders reflect the change instantly.

1NF — First Normal Form

Each column holds atomic (indivisible) values. No repeating groups or arrays in cells.

2NF — Second Normal Form

Must be in 1NF. Every non-key column depends on the whole primary key, not just part of it.

3NF — Third Normal Form

Must be in 2NF. No transitive dependencies — non-key columns depend only on the PK, not other non-key columns.
